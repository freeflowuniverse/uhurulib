
# IMAP SELECT Command Specification (Plaintext)

This specification describes how an IMAP client selects a mailbox on the server using the SELECT command. It details the command syntax, parameters, server response format, and operational behavior—all assuming an unencrypted (plaintext) connection.

---

## 1. Overview

The SELECT command is used by an IMAP client to choose a specific mailbox for subsequent operations (such as FETCH, STORE, or SEARCH). When a mailbox is selected:
- The connection moves from the "Authenticated" state to the "Selected" state.
- All further message operations will operate on the selected mailbox.
- The server sends various untagged responses that provide status information about the mailbox.

---

## 2. Pre-Conditions and Connection State

- **Connection State:**  
  The client must have already authenticated (via LOGIN or AUTHENTICATE) and be in the "Authenticated" state.
  
- **Plaintext Environment:**  
  This specification assumes that all communications occur in plaintext; no transport-layer encryption is applied.

---

## 3. Command Syntax

### 3.1 Basic Format

The basic syntax for the SELECT command is:

```
<tag> SELECT <mailbox>
```

- `<tag>`: A unique identifier generated by the client (e.g., A102) to correlate the server’s responses with this command.
- `<mailbox>`: The mailbox name to be selected, provided as an *astring* (which may be an atom or a quoted string).

### 3.2 Example Command

```
A102 SELECT "INBOX"
```

This example instructs the server to select the mailbox named “INBOX” for subsequent operations.

---

## 4. Server Responses

When the server processes a SELECT command, it sends several untagged responses that convey the current state and properties of the selected mailbox. These responses typically include:

### 4.1 Mailbox Flags

- **Response:**  
  ```
  * FLAGS (<flag-list>)
  ```
- **Description:**  
  This response lists the system and user-defined flags that are applicable to messages within the mailbox.  
- **Example:**  
  ```
  * FLAGS (\Answered \Flagged \Deleted \Seen \Draft)
  ```

### 4.2 Mailbox Existence

- **Response:**  
  ```
  * <n> EXISTS
  ```
- **Description:**  
  Indicates that there are `<n>` messages in the mailbox.
- **Example:**  
  ```
  * 18 EXISTS
  ```

### 4.3 Recent Message Count

- **Response (Optional):**  
  Some servers may return a “RECENT” response, indicating how many messages have arrived since the mailbox was last selected. (Note: In some newer revisions this may be deprecated.)
- **Example:**  
  ```
  * 0 RECENT
  ```

### 4.4 UID Information

- **UIDVALIDITY:**  
  The server must provide a UIDVALIDITY value to ensure that the unique identifiers (UIDs) for messages in the mailbox remain valid.  
  **Response:**  
  ```
  * OK [UIDVALIDITY <n>] UIDs valid
  ```
- **UIDNEXT:**  
  The server may also provide a UIDNEXT value, which is the predicted UID for the next new message in the mailbox.  
  **Response:**  
  ```
  * OK [UIDNEXT <n>] Predicted next UID
  ```

### 4.5 (Optional) Mailbox List Response

- **Response (Optional):**  
  Some servers send an untagged LIST response that repeats the mailbox name and provides information on the mailbox hierarchy.
- **Example:**  
  ```
  * LIST () "/" "INBOX"
  ```

### 4.6 Tagged Completion Response

After all the untagged responses, the server sends a tagged response to signal the completion of the SELECT command:

```
<tag> OK [READ-WRITE] SELECT completed
```

- The optional response code (such as `[READ-WRITE]` or `[READ-ONLY]`) indicates the access level of the mailbox.
- The tag here will match the one sent in the SELECT command (e.g., A102).

---

## 5. Detailed Transaction Flow

Below is an example sequence of a SELECT command over a plaintext connection:

1. **Client Sends SELECT Command:**
   ```
   A102 SELECT "INBOX"
   ```

2. **Server Sends Status Responses:**
   - **Flags List:**  
     ```
     * FLAGS (\Answered \Flagged \Deleted \Seen \Draft)
     ```
   - **Existence Count:**  
     ```
     * 18 EXISTS
     ```
   - **UID Validity and UIDNEXT:**  
     ```
     * OK [UIDVALIDITY 3857529045] UIDs valid
     * OK [UIDNEXT 4392] Predicted next UID
     ```
   - **Optional Hierarchy Listing:**  
     ```
     * LIST () "/" "INBOX"
     ```

3. **Server Sends Tagged Completion:**
   ```
   A102 OK [READ-WRITE] SELECT completed
   ```

- **Explanation:**  
  The client requests to select the INBOX mailbox. The server returns a series of untagged responses to inform the client of the mailbox status (flags, message count, UID data, etc.) and finally sends a tagged OK response indicating that the mailbox has been successfully selected and that it is open for read-write operations.

---

## 6. Implementation Notes

- **Mailbox Name:**  
  The mailbox name must be provided exactly as recognized by the server. Use of quotes may be necessary if the name includes spaces or special characters.

- **Tag Consistency:**  
  Each command is prefixed with a unique tag. The server’s final tagged response will contain the same tag, ensuring that the client can match responses to the corresponding command.

- **State Transition:**  
  Once the SELECT command completes successfully, the connection state changes to “Selected”. All subsequent commands that operate on messages (e.g., FETCH, STORE) apply to this mailbox until the mailbox is deselected (e.g., via CLOSE, UNSELECT, or by issuing another SELECT).

- **Error Handling:**  
  If the mailbox does not exist or the client lacks permission to access it, the server will return a tagged NO response. The client should handle such errors by notifying the user or taking corrective action.

- **Response Caching:**  
  The client should update its internal state with the mailbox attributes (FLAGS, EXISTS, UIDVALIDITY, UIDNEXT) to synchronize with the server.

---

## 7. Summary

- **Purpose:**  
  The SELECT command enables an IMAP client to open a mailbox for message operations.

- **Syntax:**  
  ```
  <tag> SELECT <mailbox>
  ```
  where `<mailbox>` is provided as an astring.

- **Server Responses:**  
  The server sends several untagged responses, including:
  - Mailbox FLAGS (listing supported flags)
  - The number of messages in the mailbox (EXISTS)
  - UIDVALIDITY and UIDNEXT values for message tracking
  - Optionally, a LIST response with the canonical mailbox name  
  The command concludes with a tagged OK response indicating successful selection (and may include access mode like `[READ-WRITE]`).

- **Operational Impact:**  
  A successful SELECT places the connection in the Selected state, making the mailbox active for all subsequent operations.
